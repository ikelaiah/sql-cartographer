# SQL Cartographer v3.3.0 task checklist

**Status:** Proposed; no tasks have been executed.
**Read first:** [Implementation plan](v3.3.0-plan.md) and
[roadmap](../docs/plans/v3.3.0-to-v5.0.0.md).

Dependencies refer to task numbers. File lists name primary authored files;
split a task if wiring, fixtures, or documentation take it beyond about five.
Generated runtime changes accompany source changes. The commands below are
future implementation checks, not checks run for this documentation proposal.

## 01. Record the navigation baseline

- [ ] Review the proposed journey and toolbar/filter sketches.
  - Acceptance: Five reusable fixtures cover a small flow, long procedure,
    250-node estate, duplicate labels/multiple sources, and document/region
    findings. Record current actions and sketches at desktop/stacked/200% zoom.
    Agree search fields, result ordering, and clear/focus behaviour.
  - Verify: Manual walkthrough against the v3.3.0 criteria; inspect source-field
    ownership in existing graphs and diagnostics.
  - Dependencies: None; identify remaining v3.2.0 release blockers.
  - Files: `docs/plans/v3.3.0-review.md` (new), existing fixture modules under
    `tests/` (at most two), `tasks/v3.3.0-plan.md` if decisions change.
  - Size: Small; no runtime implementation.

## 02. Add a pure flow-search model

- [ ] Match existing nodes and return deterministic results.
  - Acceptance: Case-insensitive label/full-object matching, empty/no-result
    behaviour, and duplicate labels have fixtures. Result identity/context comes
    from recorded data. Graphs and analysis counts are unchanged.
  - Verify: `npm run typecheck`; `npx tsc --project tsconfig.strict.json`;
    `npm run build` then `npm test -- --suite golden`.
  - Dependencies: 01.
  - Files: `src/ui/flow-diagram.ts`, `src/types.d.ts` only if needed,
    `tests/flow-search.ts` (new), `tests/index.html`, `tests/tests.ts`.
  - Size: Small; keep the helper in the existing strict module.

### Checkpoint A — Review matching and interaction

- [ ] Baseline and helper fixtures agree with the intended journey. Adjust
  criteria before adding controls if the graph classes need different context.

## 03. Wire Flow Find controls

- [ ] Add labelled Find, result count, previous/next, and clear controls.
  - Acceptance: Keyboard users select and frame a result through the existing
    inspector/focus actions. Controls wrap at stacked width and 200% zoom.
    Shortcuts do not intercept editor/form typing; no-results is understandable.
  - Verify: `npm run build`; `npm test -- --suite ui`; keyboard walkthrough at
    1366×768, 768×1024, and actual 200% browser zoom.
  - Dependencies: 02, Checkpoint A.
  - Files: `index.html`, `styles.css`, `src/app.ts`,
    `src/ui/flow-diagram.ts`, `tests/ui-tests.ts`.
  - Size: Medium; pure matching is already delivered in 02.

## 04. Make source navigation and selection recovery reliable

- [ ] Exercise Find through refresh, resize, and input/object changes.
  - Acceptance: Navigation chooses the owning input before applying a span;
    grouped spans remain selectable. A vanished node clears selection visibly.
    Escape/clear restores focus predictably; search decoration never leaks into
    SVG exports or changes graph counts.
  - Verify: `npm run build`; `npm test -- --suite ui`; manually follow
    find → inspect → source → return on the multi-source fixture.
  - Dependencies: 03.
  - Files: `src/app.ts`, `src/ui/flow-diagram.ts`, `tests/ui-tests.ts`,
    `src/types.d.ts` if ownership callbacks need a typed refinement.
  - Size: Medium; split recovery from source ownership if required.

## 05. Filter the shared finding list

- [ ] Add severity/code filters to both pages' diagnostic lists.
  - Acceptance: Both pages show visible and total counts; clearing filters
    restores all findings. Document findings have no fabricated source link.
    Existing source callbacks and escaped text remain safe under hostile input.
  - Verify: `npm run build`; `npm test -- --suite ui`;
    `npm test -- --suite erd-ui`; include focused hostile-message cases.
  - Dependencies: 01; integrate after 03 so toolbar conventions are settled.
  - Files: `src/ui/diagnostics.ts`, `src/app.ts`, `src/ui/erd-page.ts`,
    `tests/ui-tests.ts`, `tests/erd-ui.ts`.
  - Size: Medium; split page wiring if shared styles require another slice.

### Checkpoint B — Review the complete journey

- [ ] Find, filters, keyboard actions, owning-source navigation, recovery, and
  exported styling behave consistently. Re-scope before adding more controls.

## 06. Teach the journey and its implementation

- [ ] Add a small Find/filter walkthrough and contributor trace.
  - Acceptance: The user example explains neighbour focus and uncertainty.
    The contributor can trace helper → controller → view without hidden storage
    or analysis changes. Terms match existing Find/diagnostic vocabulary.
  - Verify: Follow the example from a clean browser session; check relative
    links and code references against the delivered source.
  - Dependencies: 04, 05, Checkpoint B.
  - Files: `docs/USER_GUIDE.md`, `docs/DEVELOPMENT.md`, `docs/GLOSSARY.md`
    only if needed, `src/samples.ts` only if an existing lesson cannot serve.
  - Size: Small.

## 07. Capture review evidence and resolve blockers

- [ ] Review the release journey in real browsers.
  - Acceptance: Five fixtures have legible light/dark captures at the two
    desktop sizes and stacked width. Actual 200% browser zoom and keyboard
    review is recorded. Two non-author reviewers attempt the journey; blocking
    failures are fixed and missing evidence is stated honestly.
  - Verify: Manual review; `npm test -- --suite ui` and
    `npm test -- --suite erd-ui` after any fixes; Firefox critical-path review.
  - Dependencies: 06.
  - Files: `docs/plans/v3.3.0-review.md`, `docs/assets/v3.3.0/` captures.
    Runtime fixes become separate small fixture-backed tasks before closing 07.
  - Size: Medium; arrange reviewers during 01.

### Checkpoint C — Release decision

- [ ] Required outcomes and review evidence are complete. Record deferred
  findings, actual effort, and changes to the next release's estimate.

## 08. Qualify the candidate and update metadata

- [ ] Run release gates and generate candidate artifacts.
  - Acceptance: Full deterministic/browser checks, strict pilot, lint,
    local-file startup, and package smoke pass. Package and lock versions agree;
    versioned metrics reflect the real fixture corpus. Inspect generated diffs
    and capture checksum evidence.
  - Verify: Commands in `docs/RELEASES.md` plus `npm test`, `npm run lint`,
    and `npx tsc --project tsconfig.strict.json`; inspect the runtime ZIP.
  - Dependencies: 07, Checkpoint C; v3.2.0 publication complete.
  - Files: `package.json`, `package-lock.json`, `docs/metrics-v3.3.0.json`
    (generated), any version constants identified during qualification.
  - Size: Small; generated `dist/` and `.release/` artifacts accompany this step.

## 09. Document and publish the reviewed release

- [ ] Complete release documentation, merge, tag, and publish.
  - Acceptance: Release note, current-version docs, and changelog accurately
    describe evidence and limits. Correctness/Firefox CI pass on the complete
    release tree and code review precedes merge. Publish that reviewed tree's
    tag, ZIP, and checksum, then verify the uploaded digest.
  - Verify: `git diff --check`; release-doc/package checks; GitHub workflow,
    tag, release asset, and digest inspection following `docs/RELEASES.md`.
  - Dependencies: 08.
  - Files: `docs/releases/v3.3.0.md`, `README.md`, `docs/ACCURACY.md`,
    `CHANGELOG.md`, `docs/RELEASES.md`. Update `docs/USER_GUIDE.md`'s version
    with its task-06 edits; update this checklist in a separate evidence slice.
  - Size: Small; publishing occurs only after the required review/merge gates.
