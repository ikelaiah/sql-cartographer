## Baseline observations

- Flow rendering fitted every graph to the canvas, which could make individual
  labels hard to read. Node actions exposed source/object navigation without a
  dedicated explanation of provenance, resolution, and relationships.
- Flow diagnostics were summarized into a warning string, losing severity,
  stable code, and source location in the page.
- Sample loading was organized around dialect or page rather than a named
  learning goal. It did not protect non-empty input with a consistent
  replacement prompt.
- Presentation and controller responsibilities were mixed in the flow and
  ERD pages, making it harder to find the code for a visible interaction.

## Release review

- **Flow reading:** The default Mermaid theme uses 13px labels. The reading
  scale floor is 0.93, and a browser assertion checks that transformed labels
  remain at least 12 CSS pixels. **Fit overview** remains explicit.
- **Selection:** Selecting a step frames its one-hop modelled neighbourhood in
  the area beside the inspector. Enter activates a node; **Clear focus**
  restores the previous viewport. Focus does not alter graph data or the
  Mermaid definition.
- **Evidence:** Source, external, synthetic, and grouped-span cases have
  focused assertions. Unknown or invalid spans receive no source action.
  Selecting a node opens context without replacing input; navigation is an
  explicit button.
- **Diagnostics:** Both pages expose severity, code, scope, message, and source
  actions only for valid spans. Hostile diagnostic text is inserted as text.
- **Long identifiers:** The ERD UI suite checks that a long qualified table
  name keeps its complete text and wraps within its card bounds.
- **Lessons:** The flow lessons select their own view/dialect; the schema
  lesson links declared keys to the query builder's row-repetition note. Tests
  exercise cancellation for guided and representative samples on both pages.
- **Maintainer walkthrough:** The decision lesson loads and explains a T-SQL
  branch; the schema lesson shows three tables and two declared foreign keys.
  Focused browser assertions cover source selection, cancellation, diagnostic
  navigation, and clean SVG output. No elapsed first-time-user timing was
  recorded.
- **Responsive/colour:** Headless Chromium screenshots were reviewed at
  1366 × 768 and 1920 × 1080 in light and dark themes for both pages. The
  768 × 1024 stacked layout was reviewed in both themes for both pages. The
  page scrolls vertically, keeps controls reachable, and shows no page-level
  horizontal overflow. The release note includes representative 1366 × 768
  light screenshots.

## Actual 200% browser zoom

An isolated Edge 155.0.4283.45 profile served the checkout from loopback on
13 October. Edge's own **Page zoom** setting was changed to **200%**. The
1366 × 900 browser window then reported a 671 × 404 CSS-pixel viewport and
device pixel ratio 2. CSS zoom remained 1; device metrics were not overridden.
The local debugging protocol supplied keyboard events and focus emulation.
This was an agent-operated browser walkthrough with visual inspection, not a
human usability session or native OS keyboard study.
The recorded [runtime observations](../assets/v3.2.0-review/evidence.json)
include the browser version, viewport, scenario checks, and request/error lists.

- Enter selected a flow step and opened its evidence; the explicit source
  action focused the editor and selected its span without changing the SQL.
  Branch views were reviewed in both themes; the temporary-table and realistic
  procedure views were also inspected.
- Cancelling a lesson preserved the existing SQL. Applying it loaded the
  intended view and instructions.
- A report dataset's source action opened the report menu and selected the
  owning XML, leaving SQL unchanged.
- The schema lesson showed three tables in both themes. Keyboard activation
  opened query mode; Space picked Customer.Name and OrderLine.ProductName.
  The generated SQL followed the two declared foreign keys through OrderHeader
  and explained row repetition and aggregate risk.
- Long ERD names retained their complete identity. The existing ERD UI test
  separately checks wrapping within card bounds.
- No page-level horizontal overflow, uncaught runtime exception, or outbound
  request was observed during the recorded loopback walkthrough.

## Findings fixed before release

| Finding | Fix and regression evidence |
| --- | --- |
| Cross-object/report offsets selected unrelated SQL | Resolve the owning SQL object, XML, or catalogue input; hide actions without a known owner |
| Old actions could replace a Tab edit or select stale XML offsets | Share input invalidation for Tab and reject stale object/auxiliary callbacks |
| Clearing SQL left old diagnostic actions | Clear diagnostics and diagram focus with the empty input |
| The stacked sticky toolbar covered the inspector at 200% | Keep the output toolbar in normal flow |
| Report menus caused horizontal page overflow | Wrap command menus in the stacked layout |
| Keyboard SVG focus scrolled the inspector outside the canvas | Clip native canvas scrolling; preserve stage-transform pan and focus |

Each new regression was observed failing before its fix. The final UI suite
passes 67/67 cases. A separate AI code reviewer approved the source ownership,
stale-input protection, responsive fixes, and release-document CI gate.

## Limits

- No independent human developer walkthrough was conducted. AI code review
  does not establish first-time-user usability.
- A timed first-time-user lesson walkthrough was not recorded. Automated tests
  cover lesson selection, cancellation, evidence inspection, keyboard node
  activation, diagnostic navigation, and clean SVG export.
- Baseline captures cover two prior v3.1.0 screens rather than the five exact
  candidate fixtures. The visual comparison is therefore directional.

These are review limits rather than parser changes. The release note records
the browser and automated verification that was completed.
